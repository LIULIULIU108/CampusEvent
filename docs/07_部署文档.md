# CampusEvent 部署文档（baseline-v1）

> 目标读者：需要在本地运行或在云服务器复现本项目的同学/教师。
>
> 本文不包含任何 API key、SSH 私钥或真实个人信息。公网仅使用虚构演示数据。

## 1. 引言

CampusEvent 是 Flask + SQLite 的校园活动报名与管理系统初始版本。部署分两种场景：

1. **本地运行**：用于开发、测试和 C1—C10 验收。
2. **云服务器**：用于提交公网地址，便于教师远程验收。

当前已部署环境：

| 项 | 值 |
| --- | --- |
| 平台 | The Vibe Hosting（免费匿名容器） |
| 公网地址 | **https://campusevent-app.thevibehosting.com** |
| 健康检查 | `/healthz` |
| 运行方式 | gunicorn，1 worker，2 threads，监听容器 80 |
| 数据库 | `/root/myapp/instance/campus_event.db` |
| 演示数据 | 3 名学生 + 4 个活动（虚构） |
| 冷启动 | 闲置约 10 分钟休眠，首次访问唤醒约 1—3 秒 |

## 2. 环境配置

### 2.1 本地环境

| 软件 | 版本/要求 |
| --- | --- |
| Python | 3.11+（验证环境 3.12.14） |
| pip | 随 Python |
| 浏览器 | Chrome/Edge 等现代桌面浏览器 |
| 操作系统 | Windows / macOS / Linux |

```powershell
cd D:\CampusEvent
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

`requirements.txt`：

```text
Flask>=3.0,<4.0
tzdata>=2024.1
pytest>=8.0
```

> Windows 必须安装 `tzdata`，否则 `ZoneInfo("Asia/Shanghai")` 会失败。

初始化并启动：

```powershell
python cli.py seed-demo     # 首次：3 名学生 + 4 个活动
python run.py               # http://127.0.0.1:5000/
```

环境变量（可选）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `CAMPUSEVENT_HOST` | `127.0.0.1` | 监听地址 |
| `CAMPUSEVENT_PORT` | `5000` | 端口 |
| `CAMPUSEVENT_DEBUG` | `0` | 生产必须为 `0` |
| `CAMPUSEVENT_DATABASE` | `instance/campus_event.db` | SQLite 路径 |
| `CAMPUSEVENT_SECRET_KEY` | 开发默认值 | 生产必须改为随机值 |
| `CAMPUSEVENT_ADMIN_PASSWORD` | `admin123` | 演示密码；生产必须修改 |

### 2.2 云服务器环境

平台为 Ubuntu 容器，需：

- Python 3.11+（当前 3.12.3）
- 可访问 PyPI（安装 Flask/gunicorn/tzdata）
- 平台自动分配 HTTPS 子域，无需自建 Nginx/证书
- 仅开放 HTTP 80（平台路由到子域）；无需安全组配置

> 免费容器 256 MB RAM；本项目 gunicorn 1 worker 足够。不要添加 keep-alive/自唤醒脚本，休眠是免费额度的一部分。

## 3. 项目部署

### 3.1 方式 A：使用仓库内脚本（推荐，需本地有凭据）

`.thevibehosting.json` 与 `.thevibehosting_key` 保存在本地，已加入 `.gitignore`，**不得提交**。

```powershell
# 1. 打包并上传（排除 .git/.venv/instance/密钥/docs/tests）
.\deploy\deploy.ps1

# 2. 远端脚本会自动：
#    - 校验 hostname 与 /root/www
#    - 解包到 /root/myapp
#    - 创建 .venv、安装 requirements + gunicorn
#    - 初始化 SQLite、写入演示数据
#    - 写 /root/run.sh 并启动 gunicorn
#    - curl /healthz 自检
```

### 3.2 方式 B：手工部署（可复现）

```bash
# 本机打包
tar -czf deploy.tar.gz --exclude=.git --exclude=.venv --exclude=instance \
  --exclude=.thevibehosting.json --exclude=.thevibehosting_key \
  app run.py cli.py requirements.txt pytest.ini

# 上传（使用平台返回的 ssh 命令中的 host/port）
scp -i .thevibehosting_key -o IdentitiesOnly=yes -P <port> deploy.tar.gz root@<host>:/root/deploy.tar.gz
scp -i .thevibehosting_key -o IdentitiesOnly=yes -P <port> deploy/remote_setup.sh root@<host>:/root/setup.sh

# 远端执行
ssh -i .thevibehosting_key -o IdentitiesOnly=yes -P <port> root@<host> \
  "sed -i 's/\r$//' /root/setup.sh && bash /root/setup.sh"
```

远端 `/root/run.sh` 关键内容：

```bash
#!/usr/bin/env bash
cd /root/myapp
export CAMPUSEVENT_DATABASE=/root/myapp/instance/campus_event.db
export CAMPUSEVENT_SECRET_KEY=<随机值>
export CAMPUSEVENT_ADMIN_PASSWORD=admin123
exec .venv/bin/gunicorn --bind 0.0.0.0:80 --workers 1 --threads 2 --timeout 60 'app:create_app()'
```

### 3.4 更新部署

```powershell
# 重新打包上传，远端脚本会复用 .venv 和数据库
.\deploy\deploy.ps1
```

如果只更新代码、不重建数据库：

```bash
cd /root/myapp
tar -xzf /root/deploy.tar.gz
pkill -f '[r]un.sh'   # 平台约 3 秒后自动用 run.sh 拉起
```

### 3.5 备份与恢复

```bash
# 备份（本机执行）
scp -i .thevibehosting_key -o IdentitiesOnly=yes -P <port> \
  root@<host>:/root/myapp/instance/campus_event.db ./campus_event.db

# 恢复：停服务后覆盖回同一路径，再让 run.sh 重启
```

SQLite 单文件；停止写入后复制即可。演示数据可随时用 `python cli.py seed-demo` 重建（仅空库写入）。

## 4. 常见问题

| 现象 | 原因/处理 |
| --- | --- |
| 首次打开 1—3 秒空白 | 容器休眠后唤醒，等待即可；不要加保活脚本 |
| `502` | 部署脚本重建 run.sh 的几秒窗口，等待自动重启 |
| `ModuleNotFoundError: tzdata` | 远端/本地未安装 `tzdata`，`pip install -r requirements.txt` |
| `pip install` 失败 | 检查容器出网；可在本地下载 wheel 后 scp 到远端离线安装 |
| 公网显示旧页面 | 重新执行部署；确认 gunicorn 进程已由 run.sh 重启 |
| 管理员无法登录 | 检查 `CAMPUSEVENT_ADMIN_PASSWORD`；默认仅用于演示 |
| 数据库锁定 | 单 worker + `BEGIN IMMEDIATE`；避免多 worker 同时写 |

## 5. 安全与范围说明

- 公网仅部署虚构演示数据；不要上传真实学生信息。
- 演示管理员密码为 `admin123`，生产必须通过环境变量修改；演示版无 CSRF token、无登录限流。
- `.thevibehosting.json`、`.thevibehosting_key`、`.env`、数据库文件均不得提交 Git。
- 免费计划要求页脚保留托管平台链接；`app/templates/base.html` 已包含。
- 需求变更阶段尚未实施；CR 发布后应重新部署 `change-v2` 并重复本文验证步骤。
