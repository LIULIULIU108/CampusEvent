## 5. 缺陷与修复记录

| 编号 | 问题/复现 | 原因 | 修复与验证 |
| --- | --- | --- | --- |
| D-01 | Windows 启动报 `ZoneInfoNotFoundError: Asia/Shanghai` | Python 3.12 Windows 未自带 IANA 时区库 | `requirements.txt` 增加 `tzdata`；安装后启动/测试通过 |
| D-02 | 并发或重复提交可能产生两条有效报名 | 应用层先查后插存在竞态 | 增加部分唯一索引 `ux_registration_active` + `BEGIN IMMEDIATE`；`test_unique_index_blocks_duplicate_active_insert` 等通过 |
| D-03 | 通知写入失败可能影响报名事务 | 通知与报名同事务/直接耦合 | 提交后发布事件；观察者失败写 `notification_attempt=FAILED`，不回滚报名；`test_notification_failure_is_logged_without_rollback` 通过 |
| D-04 | 验收脚本把顶部 flash 中的活动名当成表格行，导致后续用例操作到错误活动 ID | 验收脚本正则从 flash 开始匹配 | 改为从 `<td class="title-cell">` 匹配；清空数据库重跑，C1—C10 全部通过 |
| D-05 | 批准时可能超容量或重复批准 | 审批未在写事务内复查状态/名额 | `BEGIN IMMEDIATE` 内复查名额，`UPDATE ... WHERE status='PENDING'` 检查行数；`test_approve_full_keeps_pending` 等通过 |

> D-04 属于测试工具缺陷，已如实记录，不计入应用功能缺陷数量；应用侧 D-01—D-03、D-05 均有自动化测试复现。

## 6. 覆盖边界与已知限制

已覆盖：两类报名、满额、重复、取消、审批、审批满额、活动开始、权限、校验、通知失败、事件去重、持久化、删除/容量/报名方式约束。

未覆盖/未实施：

- **需求变更与回归**：CR 未发布，无变更版类图、影响分析、回归失败数、可维护性指标。
- CSRF：演示版未实现 token；已在 README/设计说明标注。
- 高并发：SQLite 单写者；未做压测。
- 真实邮件/短信：不在初始范围。
- 分页/大数据量：未实现。
- 浏览器兼容矩阵：仅本机 Edge 验证。
